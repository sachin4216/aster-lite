# Troubleshooting log

Errors hit while building Aster Lite, with the cause and the fix. Newest entries go at the bottom.

Each entry follows the same template:

- **Symptom:** what you saw, with the key line of the error
- **Cause:** why it happened
- **Fix:** what resolved it
- **How to recognise it next time:** the shortcut
- **Interview takeaway:** the concept behind it, if there is one

## 1. discovery-server fails with "No qualifying bean of type TransportClientFactories"

**Date:** 7 October 2026 · **Service:** discovery-server · **Stack:** Spring Boot 4.1.1, Spring Cloud 2025.1.3

**Symptom**

Starting discovery-server logs an error from `EurekaRegistration`:

```text
ERROR o.s.c.n.e.s.EurekaRegistration : error getting CloudEurekaClient

UnsatisfiedDependencyException: Error creating bean with name 'scopedTarget.eurekaClient' ...
No qualifying bean of type
'com.netflix.discovery.shared.transport.jersey.TransportClientFactories<?>' available
```

**Cause**

The module was still the default project generated by start.spring.io:

- The main class had no `@EnableEurekaServer`.
- `application.yaml` contained only the application name.

The Eureka Server starter also contains the Eureka **client**. With no configuration telling it otherwise, the client assumed this application should register with a Eureka server somewhere else, and failed while building the HTTP transport it needs for that.

**Fix**

1. Add `@EnableEurekaServer` to `DiscoveryServerApplication`.
2. Tell the client not to register or fetch, in `application.yaml`:

```yaml
server:
  port: 8761
spring:
  application:
    name: discovery-server
eureka:
  client:
    register-with-eureka: false
    fetch-registry: false
```

3. Restart and open `http://localhost:8761`. The Eureka dashboard loads.

**How to recognise it next time**

An error mentioning `eurekaClient`, `CloudEurekaClient` or `EurekaRegistration` on the **server** means the server is behaving like a client. Check the two `false` properties first.

The `LoadBalancerCaffeineWarnLogger` warning that appears beside it is unrelated and harmless in development.

**Interview takeaway**

A Eureka server is also a Eureka client. In a single-node setup you switch the client behaviour off with `register-with-eureka: false` and `fetch-registry: false`. In a high-availability setup you leave both on and point each server at its peers, so the registries replicate to each other.

## 2. `.gitignore` was created as a folder, so Git ignored nothing

**Date:** 7 October 2026 · **Area:** Git setup

**Symptom**

`git status` lists `target/` and `.idea/` as untracked files, even though `.gitignore` exists.

**Cause**

Two mistakes in a row, both from creating the file in Windows File Explorer:

- First `.gitignore` was created as an empty **directory**, not a text file.
- Then it was created as a text file, but Windows hides file extensions by default, so the file was really named `.gitignore.txt`.

Git only reads ignore rules from a **file** named exactly `.gitignore`, with no extension.

**Fix**

1. Delete the `.gitignore` folder.
2. Create the file from PowerShell or IntelliJ, not File Explorer. In IntelliJ: right-click the root, **New → File**, type `.gitignore`. To rename a wrongly named one in PowerShell: `Rename-Item .gitignore.txt .gitignore`.
3. Add the rules:

```text
target/
.idea/
*.iml
*.log
.env
```

4. If `target/` or `.idea/` was already committed, remove it from Git but keep it on disk:

```bash
git rm -r --cached target .idea
git commit -m "Stop tracking build output and IDE files"
```

**How to recognise it next time**

Run `git status` before the first commit of any new project. If build output or IDE folders appear in the list, the ignore file is missing or wrong.

To test a rule directly, ask Git which rule ignores a path. No output means nothing ignores it:

```bash
git check-ignore -v .idea
```

Turn on **View → Show → File name extensions** in File Explorer so a hidden `.txt` cannot happen again.

Note: the IntelliJ terminal on this machine is PowerShell. Command Prompt syntax such as `||` and `2>nul` does not work there.
